# בוט ידע משפחתי לשמחות (RAG בעברית)

בוט שיחה שעונה על שאלות על שמחות המשפחה (בר מצווה, ברית, אירוסין) **אך ורק** על סמך מסמכי המשפחה, ומציג את המקורות שעליהם התשובה נשענת.

## מבנה הפרויקט

| קובץ | תפקיד |
|---|---|
| `config.py` | כל ההגדרות: מודלים, top K, גודל Chunk, חפיפה, נתיבים |
| `models.py` | יצירת מודל ה-Embeddings ומודל השפה |
| `build_index.py` | בניית המאגר (חלוקה ל-Chunks, Embeddings, שמירה ב-ChromaDB) |
| `rag.py` | אחזור ויצירת תשובה עם מקורות |
| `app.py` | ממשק צ'אט Streamlit בעברית, RTL |
| `test_rag.py` | בדיקה עם 6 שאלות (אחת מהן ללא תשובה במאגר) |
| `sample_data/example.md` | דוגמה קטנה (בדויה) לפורמט הקבצים |

## הרצה

```bash
./setup.sh                    # ב-Windows: setup.bat. יוצר סביבה, מתקין חבילות ויוצר .env
# ממלאים ANTHROPIC_API_KEY בקובץ .env
# שמים את קבצי ה-.md בתיקייה data/ (example.md שם לניסיון, מוחקים אותו לפני הנתונים האמיתיים)
source .venv/bin/activate     # ב-Windows: .venv\Scripts\activate

python build_index.py         # בניית המאגר; בטוח להריץ שוב
streamlit run app.py          # הממשק
python test_rag.py            # בדיקות; מייצר test_report.md
```

ההרצה הראשונה מורידה את מודל ה-Embeddings (כ-2GB עבור `bge-m3`).

## ארכיטקטורה

```
 data/*.md ──► build_index.py ──► ChromaDB (וקטורים + metadata)
                                          │
 שאלה ──► Embedding ──► top K Chunks ────┘
                              │
                              ▼
        Claude: תשובה רק מהקטעים + ציטוט [מספר]
                              │
                              ▼
        תשובה + מקורות (שמחה › פריט, מזהה, סוג, קובץ, קטע טקסט)
```

מתי המערכת עונה "אין לי מידע": (1) המודל מונחה להשיב במשפט קבוע כשהקטעים אינם מכילים תשובה; (2) אופציונלית, `MIN_SCORE` מסנן תוצאות חלשות לפני שהן מגיעות למודל. כשאין מידע, לא מוצגים מקורות, כדי לא להציג קטעים שלא תומכים בשום תשובה.
כשיש תשובה, מוצגים הקטעים שהמודל ציטט (ואם לא ציטט, כל הקטעים ששימשו כהקשר).

## הבחירות הטכנולוגיות

- **חלוקה:** לפי כותרות `##`, פריט אחד = Chunk אחד. פריט הוא יחידת משמעות שלמה (למשל "צילום" עם מחיר, ספק ולקח), ולכן חלוקה לפי גודל קבוע הייתה חותכת אותו באמצע. שדות הפריט (מזהה, סוג, שם השמחה) נשמרים גם כ-metadata לתצוגת מקורות, והטקסט המלא של הפריט, כולל השדות, נכנס ל-Embedding, כך שהשאלה "מה עלה האולם בבר המצווה של דוד" מתאימה גם לפי שם השמחה.
- **חפיפה:** בין פריטים אין חפיפה, כי הם בלתי תלויים. רק פריט שחורג מ-`CHUNK_SIZE` מפוצל עם חפיפה של 100 tokens (`SentenceSplitter`), וחלקי ההמשך מקבלים את כותרת הפריט.
- **top K:** פריטים קצרים, ושאלות על "כל הספקים" או "כל הלקחים" נוגעות בכמה פריטים. ערך נמוך מדי מפספס, גבוה מדי מכניס רעש. מכוונים ב-`config.py` לפי תוצאות `test_rag.py`.
- **Embeddings: `BAAI/bge-m3`.** מודל רב-לשוני עם ביצועים טובים בעברית, רץ מקומית (ללא מפתח נוסף ועלות, והמסמכים המשפחתיים לא יוצאים מהמחשב), ולא דורש קידומות. חלופה קלה יותר: `intfloat/multilingual-e5-base` עם `EMBED_QUERY_PREFIX="query: "` ו-`EMBED_TEXT_PREFIX="passage: "`. **אחרי החלפת מודל חובה להריץ `build_index.py` מחדש.**
- **מודל שפה: Claude (`claude-sonnet-5-5`).** עברית טובה, ציות טוב להוראת "רק מהקטעים", וטמפרטורה 0 לתשובות יציבות. אפשר לדרוס ב-`LLM_MODEL`. למודלי Anthropic אין Embeddings, ולכן Embeddings מקומי.
- **ChromaDB** במצב persistent עם מרחק cosine. בכל בנייה ה-collection נמחק ונוצר מחדש, וכך אין כפילויות בהרצה חוזרת.
- **התעלמות מהוראות במסמכים:** הפרומפט מציין שהקטעים הם נתונים בלבד.

## תיעוד בעיות מהבדיקות

| # | בעיה (שאלה ומה קרה) | סיבה | תיקון | תוצאה אחרי התיקון |
|---|---|---|---|---|
| 1 | הצגת מקורות במצב שבו אין תשובה במאגר | החזרת קטעים על ידי מנגנון האחזור למרות היעדר מידע רלוונטי | עדכון פונקציית התשובה כך שלא יוצגו מקורות כלל במצב של חוסר מענה תקף | מניעת הצגת מקורות שאינם תומכים בתשובה |
| 2 | זמני תגובה איטיים בתהליך האחזור | גודל Chunk נמוך מדי בשילוב ערך `top_k` גבוה יצרו עומס באחזור | הגדלת גודל ה-Chunks והקטנת ערך ה-`top_k` | שיפור משמעותי בזמני התגובה וביעילות השליפה |
| 3 | כשל בטעינת מודל השפה | היעדר הגדרה תקינה של משתנה `LLM_MODEL` בקובץ ההגדרות | הגדרה מפורשת של `LLM_MODEL` | טעינה יציבה ותקינה של המודל ללא שגיאות |
